# Interior AI — MVP

Система, которая принимает план квартиры, хранит его как **редактируемую
модель** (помещения, стены, двери, окна, мебель), применяет правки текстом
и отдаёт 2D-план, DXF и 3D-модель.

Главный принцип: правки меняют **параметры объектов**, а не рисуют поверх
картинки. Поэтому всё, что не упомянуто в команде, остаётся как было.

## Структура

```text
interior-ai/
  .env.example          шаблон настроек (без секретов)
  .gitignore
  docker-compose.yml
  backend/
    app/
      models.py         модель данных
      geometry.py       правки и проверки
      commands.py       разбор команд (правила / LLM)
      storage.py        проекты и версии
      render2d.py       2D-план в SVG
      export.py         DXF и OBJ
      seed.py           тестовый план из брифа

    web/index.html      интерфейс

```

## Запуск

```bash
cd backend
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp ../.env.example ../.env
python -m app.seed                 # создать тестовый проект
uvicorn app.main:app --reload      # http://localhost:8000
pytest -q                          # проверки
```

Через Docker:

```bash
cp .env.example .env
docker compose up --build
```

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/health` | состояние, включена ли модель |
| GET | `/api/projects` | список проектов |
| POST | `/api/projects/{id}/command` | текстовая команда → правки, отчёт, SVG |
| POST | `/api/projects/{id}/operations` | структурированные правки (для агентов) |
| POST | `/api/projects/{id}/plan.svg` | 2D-план |
| GET | `/api/projects/{id}/revisions` | история |
| POST | `/api/projects/{id}/revert/{rev}` | откат |
| POST | `/api/projects/{id}/validate` | проверка геометрии |
| GET | `/api/projects/{id}/export.dxf` | экспорт в AutoCAD |
| GET | `/api/projects/{id}/model.obj` | 3D-модель |
| POST | `/api/projects/{id}/duplicate` | копия для варианта планировки |
| POST | `/api/projects/{id}/upload` | загрузка исходного плана |

## Подключение языковой модели

В `.env`:

```text
LLM_ENABLED=1
LLM_BASE_URL=https://api.openai.com/v1   # любой совместимый провайдер
LLM_MODEL=ваша-модель
LLM_API_KEY=ваш-ключ
```

Модель получает описание проекта и команду и возвращает **список операций
в JSON**. Изменения выполняет наш код, поэтому модель не может сломать
геометрию или изменить чужие объекты. Если модель недоступна — включаются
правила.

## Ограничения текущей версии

- Планировка заполняется из **демонстрационного набора**, а не из
  загруженного файла: распознавание изображений — следующий этап.
- Правки разбираются **по ключевым словам** в режиме без модели; сложные
  формулировки лучше проводить через LLM.
- Проверки геометрии упрощённые: мебель — прямоугольники, стены — прямые.
- Хранение — JSON в файлах; для нескольких пользователей нужна база данных.
